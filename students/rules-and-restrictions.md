# Правила и запрещённые действия

## Правила личной работы

- Работайте только в ветке `student/<группа>/<фамилия-инициалы>`.
- Размещайте результаты работы только в директории `<группа>/<фамилия-инициалы>/`.
- Перед изменениями проверяйте текущую ветку командой `git branch --show-current`.
- Перед коммитом проверяйте состав изменений командами `git status`, `git diff` и `git diff --cached`.
- Используйте содержательные сообщения коммитов, по которым можно понять суть изменения.
- Получайте обновления преподавателей из `master` только в соответствии с общей инструкцией.
- Для сдачи задания создавайте Pull Request из личной ветки в указанную преподавателем ветку `submission/<задание>`.
- При обнаружении чужих или неожиданных изменений прекратите работу и сообщите преподавателю.

## Запрещённые действия

Студентам запрещено:

- отправлять изменения непосредственно в `master`;
- отправлять изменения непосредственно в ветки `submission/<задание>` или самостоятельно объединять направленные в них Pull Request;
- изменять, переименовывать или удалять чужие ветки;
- изменять файлы в директориях других студентов;
- создавать ветки или директории от имени другого студента;
- применять `git push --force` или `git push --force-with-lease`;
- самостоятельно переписывать опубликованную историю коммитов;
- изменять адрес удалённого репозитория, локальную идентификацию компьютера, SSH-ключи и другие параметры доступа;
- копировать с рабочего компьютера приватные ключи, токены и другие учётные данные;
- изменять `.github/`, GitHub Actions, учебные материалы и служебные файлы курса без прямого указания преподавателя;
- размещать пароли, токены, приватные ключи и другие секреты;
- размещать персональные данные, не предусмотренные заданием;
- загружать чужую работу под своим именем;
- намеренно нарушать доступность репозитория или мешать работе других студентов.

Наличие технической возможности выполнить действие не означает разрешения на него. GitHub, журнал аудита организации и история Git сохраняют сведения о действиях пользователей, включая коммиты, отправку изменений, создание и удаление веток, Pull Request и изменения доступа. Администраторы могут использовать эти сведения при разборе инцидентов.

За нарушение правил в зависимости от характера и последствий могут применяться учебные и дисциплинарные санкции в соответствии с правилами курса и университета.
