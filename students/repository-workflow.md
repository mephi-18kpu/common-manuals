# Работа с учебным репозиторием

В примерах используются следующие значения:

```text
Репозиторий:        2026-autumn-python-course
Группа:             b24-601
Студент:            student-07
Задание:            lab-01
Ветка задания:      submissions/lab-01
Постоянная ветка:   student/b24-601/student-07
Рабочая директория: D:/Study
Личная директория:  b24-601/student-07/
Ветка отчётной работы: student-submission/lab-01/b24-601/student-07
```

Замените их значениями, которые сообщил преподаватель. Не копируйте имена веток из примера без изменений.

## 1. Первоначальное клонирование

Перейдите в директорию, предназначенную для учебных репозиториев, и выполните:

```bash
cd "D:/Study"
git clone https://github.com/mephi-18kpu/2026-autumn-python-course
cd 2026-autumn-python-course
```

Если преподаватель выдал другую ссылку для клонирования, используйте её. На аудиторном компьютере доступ выполняется через закреплённый за ним аккаунт GitHub; не заменяйте его личным аккаунтом и не переносите сохранённые данные для входа между компьютерами.

Проверьте адрес удалённого репозитория и состояние рабочей копии:

```bash
git remote -v
git status
```

Адрес должен указывать на репозиторий курса в организации `mephi-18kpu`.

## 2. Проверка идентификации компьютера

В каждом клоне администратор настраивает технического автора коммитов. Проверьте настройку:

```bash
git config --global --get user.name
git config --global --get user.email
```

Если эти параметры не настроены, то обратитесь к преподавателю.

## 3. Выбор рабочей ветки

### Повседневная разработка

Для повседневной разработки используется постоянная ветка `student/<группа>/student-<номер-студента-в-группе>`. Если она уже существует на GitHub, подключите её:

```bash
git switch -c student/b24-601/student-07 --track origin/student/b24-601/student-07
```

Если Git не находит удалённую ветку, сначала обновите сведения о ветках командой `git fetch origin`, а затем повторите команду подключения. Если ветки по-прежнему нет на GitHub, не создавайте её самостоятельно. Обратитесь к преподавателю: он передаст администратору группу и номер студента, после чего администратор подготовит ветку от согласованного состояния `master`.

### Отдельная отчётная работа

До начала задания администратор создаёт на GitHub общую ветку `submissions/<задание>` и персональные ветки всех студентов от одного согласованного состояния `master`. Студент не создаёт ветку отчётной работы самостоятельно, а подключает уже существующую удалённую ветку:

```bash
git switch -c student-submission/lab-01/b24-601/student-07 --track origin/student-submission/lab-01/b24-601/student-07
```

Параметр `--track` связывает локальную ветку с одноимённой удалённой веткой, поэтому для дальнейшей отправки и получения собственных изменений достаточно команд `git push` и `git pull --ff-only`.

Если ветка уже существует и в локальном клоне:

```bash
git switch student-submission/lab-01/b24-601/student-07
git pull --ff-only
```

Если Git не находит удалённую ветку, сначала обновите сведения о ветках командой `git fetch origin`, а затем повторите команду подключения. Если ветки по-прежнему нет, её имя не совпадает с выданным идентификатором или Git предлагает создать ветку без связи с `origin`, остановитесь и обратитесь к преподавателю. Преподаватель передаст запрос администратору, который создаст пропущенную ветку от сохранённого исходного commit задания; студенту нельзя создавать её от текущего состояния `submissions/<задание>` или другой ветки.

Перед началом работы проверьте:

```bash
git branch --show-current
git status
```

### Локальные вспомогательные ветки

Для отдельного этапа работы можно создать локальную ветку от текущей рабочей ветки. Такая ветка остаётся только на компьютере и не отправляется на GitHub:

```bash
git switch student/b24-601/student-07
git pull --ff-only
git switch -c local/refactoring
```

После завершения этапа сохраните изменения в коммитах, вернитесь в рабочую ветку и объедините локальную ветку:

```bash
git switch student/b24-601/student-07
git merge --ff-only local/refactoring
git push
```

Для отчётной работы вместо постоянной ветки в командах используется выданная `student-submission/<задание>/<группа>/student-<номер-студента-в-группе>`. Если `--ff-only` отклоняет объединение, не переписывайте историю и обратитесь к преподавателю. Не выполняйте `git push -u origin` для локальной вспомогательной ветки.

## 4. Начало каждого занятия

Откройте локальный репозиторий и проверьте его состояние:

```bash
cd 2026-autumn-python-course
git status
git branch --show-current
```

Текущей должна быть постоянная ветка для повседневной разработки либо персональная ветка выполняемой отчётной работы. При необходимости переключитесь на неё и получите собственные изменения с GitHub:

```bash
git switch student-submission/lab-01/b24-601/student-07
git pull --ff-only
```

Если на другом компьютере ветка отсутствует локально, подключите её по инструкции из предыдущего раздела.

Не объединяйте в рабочую ветку обновившуюся `submissions/lab-01`: после начала приёма там могут находиться работы других студентов. Не объединяйте `master` без прямого указания преподавателя. Если преподаватель изменил материалы после начала задания, следуйте его отдельной инструкции.

## 5. Работа с файлами

Изменяйте файлы только внутри своей директории:

```text
b24-601/student-07/
```

Перед коммитом проверьте изменения:

```bash
git status
git diff
```

Добавляйте только нужные файлы, указывая их явно:

```bash
git add b24-601/student-07/path/to/file.py
git diff --cached
git commit -m "Краткое описание изменения"
```

Не используйте `git add .`, пока не проверили все отображаемые `git status` файлы.

## 6. Отправка изменений

После каждого завершённого этапа отправляйте коммиты в свою рабочую ветку:

```bash
git branch --show-current
git push
```

Постоянная ветка и ветка отчётной работы должны быть подключены к заранее созданным одноимённым веткам на GitHub командой из раздела 3. Если upstream отсутствует, не создавайте удалённую ветку через `git push -u`: проверьте имя ветки и обратитесь к преподавателю.

Обычный push разрешён, но удаление ветки и force-push запрещены ruleset. При отклонении non-fast-forward сначала получите собственные удалённые изменения; не пытайтесь обходить запрет.

## 7. Сдача задания через Pull Request

Перед созданием Pull Request убедитесь, что все изменения задания сохранены в коммитах и отправлены на GitHub:

```bash
git status
git branch --show-current
git push
```

На GitHub откройте раздел **Pull requests**, нажмите **New pull request** и выберите:

- в поле **base** — ветку задания, например `submissions/lab-01`;
- в поле **compare** — свою ветку отчётной работы, например `student-submission/lab-01/b24-601/student-07`.

Перед созданием Pull Request проверьте вкладку **Files changed**. Изменения должны относиться только к текущему заданию и находиться в вашей личной директории. В названии укажите задание и обезличенный идентификатор, например `lab-01: b24-601_student_07`.

Преподаватель проверяет работу и оставляет комментарии в Pull Request. Для исправления замечаний измените файлы в той же рабочей ветке, создайте новые коммиты и выполните `git push`. Изменения автоматически появятся в открытом Pull Request.

Не объединяйте Pull Request самостоятельно и не отправляйте изменения непосредственно в `submissions/<задание>`. После принятия работы преподаватель выполняет squash merge, и принятая версия появляется в общей ветке задания.

## 8. После принятия работы

Ветка `submissions/<задание>` содержит принятые версии работ и не объединяется с `master` или ветками других заданий. Ветка `student-submission/<задание>/<группа>/student-<номер-студента-в-группе>` после принятия не удаляется и больше не используется: объединённый Pull Request считается окончательной сдачей задания.

Для следующего задания администратор создаёт новую независимую ветку `submissions/*` и заранее создаёт от того же исходного состояния персональные ветки студентов, например:

```text
student-submission/lab-02/b24-601/student-07
```

Подключите выданную ветку по инструкции из раздела 3. Не создавайте её самостоятельно от предыдущей студенческой ветки или от `submissions` другого задания.

## 9. Просмотр веток и истории

Полезные команды, не изменяющие репозиторий:

```bash
git status
git branch --show-current
git branch --all
git log --oneline --decorate --graph -20
git diff
git diff --cached
```

Не переключайтесь на чужую студенческую ветку для внесения изменений.
