# Работа с учебным репозиторием

В примерах используются следующие значения:

```text
Репозиторий: 2026-autumn-python-course
Группа:      b24-601
Студент:     ivanov-ii
Ветка:       student/b24-601/ivanov-ii
Рабочая директория: D:/Study
Личная директория:  b24-601/ivanov-ii/
```

Замените их значениями, которые сообщил преподаватель. Не копируйте имя ветки из примера без изменений.

## 1. Первоначальное клонирование

Перейдите в директорию, предназначенную для учебных репозиториев, и выполните:

```bash
cd "D:/Study"
git clone https://github.com/mephi-18kpu/2026-autumn-python-course.git
cd 2026-autumn-python-course
```

Если преподаватель выдал другую ссылку для клонирования, используйте её. На аудиторных компьютерах после настройки deploy key преподаватель может выдать SSH-ссылку вместо HTTPS-ссылки.

Проверьте адрес удалённого репозитория и состояние рабочей копии:

```bash
git remote -v
git status
```

Адрес должен указывать на репозиторий курса в организации `mephi-18kpu`.

## 2. Проверка идентификации компьютера

В каждом клоне администратор настраивает технического автора коммитов. Проверьте настройку:

```bash
git config --local --get user.name
git config --local --get user.email
```

Не изменяйте эти значения самостоятельно. Если они отсутствуют или не соответствуют компьютеру и репозиторию, обратитесь к преподавателю.

## 3. Создание личной ветки

Личная ветка создаётся один раз от актуального состояния `master`:

```bash
git switch master
git pull --ff-only origin master
git switch -c student/b24-601/ivanov-ii
git push -u origin HEAD
```

Команда `git switch -c` одновременно создаёт личную ветку и переключает на неё рабочую копию. В команде `git push -u origin HEAD` обозначение `HEAD` указывает на текущую ветку, а параметр `-u` связывает её с одноимённой веткой на GitHub. Перед выполнением команды обязательно проверьте текущую ветку командой `git branch --show-current`.

Создайте личную директорию и добавьте в неё первый файл, предусмотренный заданием. Git не хранит пустые директории.

```bash
mkdir b24-601/ivanov-ii
```

Если личная ветка уже существует на GitHub, создавать её повторно не нужно:

```bash
git fetch origin
git switch --track origin/student/b24-601/ivanov-ii
```

Команда `git fetch origin` получает сведения о ветках с GitHub, не изменяя текущую ветку и рабочие файлы. Команда `git switch --track` создаёт локальную ветку, связывает её с существующей веткой на GitHub и переключает рабочую копию. Использовать вместо этой последовательности `git pull origin` нельзя: `git pull` не создаёт и не переключает ветку, а пытается объединить полученные изменения с текущей веткой.

## 4. Начало каждого занятия

Откройте локальный репозиторий и проверьте его состояние:

```bash
cd 2026-autumn-python-course
git status
git branch --show-current
```

Текущей должна быть личная ветка студента. При необходимости переключитесь на неё:

```bash
git switch student/b24-601/ivanov-ii
```

Получите изменения, ранее отправленные в эту ветку:

```bash
git pull --ff-only origin student/b24-601/ivanov-ii
```

Команду `git pull` следует выполнять только при отсутствии незакоммиченных изменений.

## 5. Создание коммитов

Перед добавлением файлов просмотрите изменения:

```bash
git status
git diff
```

Добавляйте только файлы текущей работы:

```bash
git add b24-601/ivanov-ii/solution.py
# Или после проверки git status добавьте все изменения:
git add .
git diff --cached
```

После проверки создайте коммит с понятным сообщением:

```bash
git commit -m "ЛР1: добавлено решение первого задания"
```

Рекомендуется создавать отдельный коммит после каждого законченного изменения. Не используйте `git add .`, не проверив предварительно `git status`: эта команда добавляет в будущий коммит все изменения в текущем репозитории.

## 6. Отправка изменений на GitHub

Отправьте коммиты в личную ветку:

```bash
git push
```

Если связь личной ветки с веткой на GitHub ещё не настроена, выполните:

```bash
git push -u origin HEAD
```

`HEAD` означает текущую локальную ветку. Параметр `-u` сохраняет связь между ней и созданной веткой на GitHub, поэтому в дальнейшем можно использовать короткие команды `git pull` и `git push`. Перед первым `push` проверьте текущую ветку командой `git branch --show-current`.

После отправки убедитесь, что команда завершилась без ошибки. При необходимости откройте свою ветку на GitHub и проверьте наличие последнего коммита.

## 7. Сдача задания через Pull Request

Для сбора и проверки работ преподаватель может создать отдельную ветку по шаблону `submission/<задание>`, например `submission/lab-01`. Студент продолжает выполнять работу в своей личной ветке и не отправляет изменения непосредственно в ветку задания.

Перед созданием Pull Request убедитесь, что все изменения задания сохранены в коммитах и отправлены в личную ветку на GitHub:

```bash
git status
git branch --show-current
git push
```

На GitHub откройте раздел **Pull requests**, нажмите **New pull request** и выберите:

- в поле **base** — указанную преподавателем ветку задания, например `submission/lab-01`;
- в поле **compare** — свою личную ветку, например `student/b24-601/ivanov-ii`.

Перед созданием Pull Request проверьте вкладку **Files changed**. Изменения должны находиться только в вашей личной директории. В названии Pull Request укажите задание, группу и фамилию с инициалами, например `lab-01: b24-601/ivanov-ii`.

Преподаватель проверяет работу и оставляет комментарии в Pull Request. Для исправления замечаний измените работу в той же личной ветке, создайте новые коммиты и выполните `git push`. Изменения автоматически появятся в уже созданном Pull Request, поэтому создавать новый Pull Request после каждого исправления не нужно.

Не объединяйте Pull Request самостоятельно. После принятия работы его объединяет преподаватель, и принятая версия появляется в общей ветке задания.

## 8. Получение обновлений из `master`

Преподаватели могут обновлять задания и материалы в `master`. Перед объединением изменений убедитесь, что ваша работа сохранена в коммитах и `git status` не показывает незакоммиченных файлов.

Обновите локальную ветку `master`:

```bash
git switch master
git pull --ff-only origin master
```

Вернитесь в личную ветку и объедините её с `master`:

```bash
git switch student/b24-601/ivanov-ii
git merge master
git push
```

Если возник конфликт, не используйте force-push. Выполните инструкции из [раздела об устранении ошибок](troubleshooting.md#конфликт-при-объединении-master).

## 9. Просмотр веток и истории

Полезные команды, не изменяющие репозиторий:

```bash
git status
git branch --show-current
git branch --all
git log --oneline --decorate --graph -20
git diff
git diff --cached
```

Не переключайтесь на чужую студенческую ветку для внесения изменений.
