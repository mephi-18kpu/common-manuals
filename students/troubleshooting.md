# Самостоятельное устранение ошибок

Перед исправлением любой проблемы выполните:

```bash
git status
git branch --show-current
git log --oneline --decorate -10
```

Внимательно прочитайте сообщение Git. Не применяйте `force-push`, не удаляйте ветки и не переписывайте опубликованную историю.

## В изменения случайно добавлен лишний файл

Если коммит ещё не создан, уберите файл из подготовленных к коммиту, сохранив его содержимое:

```bash
git restore --staged path/to/file
git status
```

Если требуется полностью отменить локальные изменения файла, используйте:

```bash
git restore path/to/file
```

Вторая команда безвозвратно удаляет незакоммиченные изменения указанного файла. Выполняйте её только если уверены, что эти изменения не нужны.

## Работа начата не в той ветке

Если коммит ещё не создан, сначала попробуйте переключиться в нужную ветку:

```bash
git switch student/b24-601/student-07/lab-01
```

Если Git не разрешает переключение из-за локальных изменений, временно сохраните их:

```bash
git stash push -u -m "Временное сохранение перед сменой ветки"
git switch student/b24-601/student-07/lab-01
git stash pop
git status
```

После `git stash pop` внимательно проверьте файлы и возможные конфликты.

## Коммит случайно создан в локальной `master`

Не выполняйте `git push`. Найдите идентификатор ошибочного коммита:

```bash
git log --oneline -5
```

Сначала создайте резервную ветку, чтобы случайные коммиты можно было восстановить:

```bash
git branch backup/master-before-reset
```

Если ветка `backup/master-before-reset` уже существует, выберите для новой резервной ветки другое имя.

Если рабочая ветка задания уже существует, перенесите нужный коммит в неё:

```bash
git switch student/b24-601/student-07/lab-01
git cherry-pick COMMIT_ID
```

Если рабочая ветка ещё не существует, не создавайте её из локальной `master`. Узнайте у преподавателя исходный commit задания, создайте от него рабочую ветку и перенесите ошибочный коммит:

```bash
git switch --no-track -c student/b24-601/student-07/lab-01 SUBMISSION_BASE_COMMIT
git cherry-pick COMMIT_ID
```

Убедитесь, что нужная работа находится в рабочей ветке и `git status` не показывает незакоммиченных изменений. Затем получите актуальное состояние GitHub и восстановите только локальную `master`:

```bash
git fetch origin
git switch master
git reset --hard origin/master
git status
```

Команда `git reset --hard origin/master` делает локальную `master` полностью совпадающей с `master` на GitHub и удаляет из неё локальные изменения. Она допустима только после создания резервной ветки и сохранения нужной работы в рабочей ветке. Не удаляйте резервную ветку самостоятельно; дальнейшие действия согласуйте с преподавателем.

Если коммит уже был отправлен в `master`, прекратите работу и немедленно сообщите преподавателю или администратору.

## Git сообщает, что рабочая ветка уже существует

Обновите сведения об удалённых ветках и подключите существующую ветку:

```bash
git fetch origin
git switch --track origin/student/b24-601/student-07/lab-01
```

Если локальная ветка с таким именем также существует:

```bash
git switch student/b24-601/student-07/lab-01
git pull --ff-only origin student/b24-601/student-07/lab-01
```

## `git push` отклонён как non-fast-forward

Убедитесь, что работаете в своей рабочей ветке задания, затем получите удалённые изменения:

```bash
git branch --show-current
git pull --rebase origin student/b24-601/student-07/lab-01
git push
```

Используйте этот способ только для собственной ветки. Если при `rebase` возникли конфликты, их можно устранить по подсказкам Git либо отменить операцию:

```bash
git rebase --abort
```

После отмены обратитесь к преподавателю.

## Начато объединение `master` или `submissions/<задание>`

Не продолжайте такое объединение самостоятельно: после начала приёма `submissions/<задание>` может содержать работы других студентов, а обновления `master` могут изменить исходное состояние задания.

Если merge ещё не завершён, отмените его:

```bash
git merge --abort
```

Если Git сообщает, что объединение не выполняется, ничего не удаляйте и обратитесь к преподавателю. Если merge уже завершён коммитом или отправлен на GitHub, также обратитесь к преподавателю: исправление зависит от состояния ветки и не должно переписывать опубликованную историю.

Если преподаватель прямо поручил выполнить объединение и возник конфликт, посмотрите список конфликтующих файлов:

```bash
git status
```

Откройте каждый файл и найдите маркеры конфликта:

```text
<<<<<<<
=======
>>>>>>>
```

Выберите правильное содержимое, удалите маркеры и добавьте исправленные файлы:

```bash
git add path/to/resolved-file
git status
git commit -m "Объединены обновления по указанию преподавателя"
git push
```

Если вы не понимаете, какую версию сохранить, отмените незавершённое объединение:

```bash
git merge --abort
```

После отмены попросите преподавателя помочь с обновлением.

## Изменения внесены за пределами личной директории

Если коммит ещё не создан, переместите файлы в личную директорию и проверьте результат:

```bash
git status
git diff
```

Если изменения уже закоммичены в рабочей ветке, создайте новый исправляющий коммит: верните посторонние файлы в исходное состояние, перенесите свою работу в личную директорию, затем снова выполните `git status`, `git add` и `git commit`. Не переписывайте уже отправленные коммиты.

## Git не может подключиться к GitHub

Проверьте интернет-соединение и адрес репозитория:

```bash
git remote -v
```

Не заменяйте адрес, аккаунт GitHub или параметры доступа самостоятельно и не входите под личным аккаунтом. Если адрес указывает на организацию `mephi-18kpu`, но доступ не работает, сообщите преподавателю номер аудитории, номер компьютера, логин аккаунта рабочего места, название репозитория и полный текст ошибки. Не отправляйте пароли, коды двухфакторной аутентификации, recovery codes, приватные ключи и токены.

## Когда необходимо обратиться к преподавателю

Обратитесь за помощью, если:
- изменение уже отправлено в `master` или чужую ветку;
- требуется удалить либо переименовать ветку;
- безопасный способ исправления не понятен;
- после `merge`, `rebase` или `stash pop` остались конфликты;
- Git сообщает об отсутствии прав доступа;
- обнаружены чужие изменения.

Сообщите название репозитория, свою ветку, номер рабочего компьютера, выполненную команду и полный текст ошибки. Пароли, ключи и токены сообщать нельзя.

Также можно обратиться к администратору по контактам, указанным в Telegram-чате или в описании [кафедры на GitHub](https://github.com/mephi-18kpu).
