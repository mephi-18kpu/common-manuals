# Создание и настройка учебного репозитория

## 1. Общая организация

- Все учебные репозитории принадлежат организации [`mephi-18kpu`](https://github.com/mephi-18kpu), а не личным аккаунтам преподавателей.
- Для каждого курса, семестра или самостоятельного набора материалов создаётся отдельный репозиторий.
- Название формируется по шаблону `<год>-<семестр>-<краткое-название>-<назначение>`.
- В качестве назначения можно использовать `course`, `materials` или другое слово, которое точнее отражает содержимое репозитория. Предпочитайте уже созданные термины для обозначения содержимого. 
- Примеры: `2026-autumn-python-course`, `2026-autumn-miluino-course`, `stm32-reference-materials`.
- Для учебных репозиториев основной веткой является `master`.
- Ветка `master` содержит общие материалы, задания, инструкции и служебные файлы. Студенческий код хранится в личных ветках и не переносится в `master`.

## 2. Ответственность администраторов организации

Администраторы организации:
- управляют репозиториями и их настройками;
- управляют командами и доступом пользователей;
- создают и применяют rulesets;
- управляют deploy keys.

## 3. Доступ преподавателей

- Администратор добавляет преподавателя в конкретный репозиторий и назначает ему роль `Maintain`.
- Преподаватель использует личный аккаунт GitHub и отвечает за действия, выполненные под этим аккаунтом.
- Если преподавателю требуется изменить настройку, недоступную с ролью `Maintain`, он обращается к администратору организации.

## 4. Формирование доступа студентов

Доступ студентов организуется через команды учебных групп:
1. Администратор создаёт в организации команду с названием учебной группы, например `b24-601`.
2. Администратор приглашает студентов в организацию и добавляет их в соответствующую команду.
3. Преподаватель сообщает администратору, какие учебные группы должны получить доступ к его репозиторию.
4. Администратор добавляет указанные команды к репозиторию с ролью `Write`.
5. Преподаватель проверяет, что нужные студенты видят репозиторий и могут отправлять изменения в личные ветки, но не могут изменять защищённую `master` напрямую.

Роль `Maintain` не позволяет преподавателю управлять доступом команд к репозиторию. Если преподаватель должен добавлять команды самостоятельно, администратор должен назначить ему роль `Admin` для этого репозитория.

## 5. Подготовка репозитория

До начала занятий преподаватель совместно с администратором проверяет:
- название, описание и видимость репозитория;
- наличие актуального `README.md`;
- наличие ссылки на общие инструкции `CommonManuals`;
- соответствие default branch принятому имени `master`;
- наличие правил именования студенческих веток и директорий;
- наличие необходимых учебных материалов и `.gitignore`;
- наличие активного ruleset для `master`;
- работоспособность примеров команд и ссылок;
- доступ преподавателей и студенческих команд.

## 6. Защита `master`

Администратор может создать ruleset для основной ветки на основе файла [`protect-default-branch.json`](../protect-default-branch.json).

Шаблон включает:
- запрет удаления default branch;
- запрет force-push и других non-fast-forward обновлений;
- обязательную линейную историю;
- обязательный Pull Request;
- один approval;
- сброс устаревшего approval после появления новых коммитов;
- обязательное разрешение обсуждений;
- только squash merge;
- обход требований Pull Request только для администраторов организации.

Перед предоставлением студентам роли `Write` преподаватель совместно с администратором проверяет, что ruleset активен и применяется к `master`.
